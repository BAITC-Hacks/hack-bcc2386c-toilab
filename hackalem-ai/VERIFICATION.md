# Проверка проекта

Фактически выполнено в среде разработки:

- `python run_tests.py`: **32 passed**, 1 предупреждение установленного Starlette о версии httpx; тесты не пропущены.
- `node --check chat-widget/public/app.js`: успешно.
- Реально запущены три процесса: uvicorn Catalog:8001, uvicorn Assistant:8002, Widget:3000. Оба /health и HTML сайта вернули HTTP 200; Catalog загрузил 4 synthetic items.
- После остановки процесса Catalog, Assistant /health продолжил возвращать 200 и catalog_service_reachable=false.
- Без LLM-ключа POST /assistant/message возвращает корректные reply_text/proposed_action/needs_confirmation/cart_url и вежливую деградацию.
- Полный трёхходовый сценарий через ASGI API обоих сервисов со scripted LLM: наличие → отсутствующий товар/аналог/предложение → подтверждение → HTML-корзина с 2 шт. и итогом 3780 ₸. Проверено, что до подтверждения корзина пуста.
- Синтетический номер карты не сохраняется в server history и не передаётся модели.

Не проверено и не заявляется как успешно пройденное:

- Docker build/Compose runtime: Docker в текущей среде отсутствует. Сами сервисы проверены прямым запуском Python. Образы требуют скачивания базового образа и Python-зависимостей.
- Вызов реальной LLM: ключ пользователя не предоставлен. Scripted tests не проверяют семантическую точность модели и все возможные prompt injection.
- Реальная форма ответа ekt.kz и авторизованная синхронизация с партнёром: адаптер нуждается в сверке с настоящим payload.
- Визуальная проверка реальным браузером, мобильная клавиатура и внешние шрифты: инфраструктура browser preview для static в этой среде недоступна. Вёрстка содержит responsive CSS и visualViewport, но ручной browser QA не выполнен.
- Запись в реальную корзину ekt.kz, оплата, вложения, достоверные условия доставки/оплаты партнёра: необходимы дополнительные данные и контракты.

Опубликованная версия — статический интерфейс. Для рабочего backend запустите проект из архива и настройте env, как описано в README.

## Обновление локального ИИ

- 39 tests passed: исходные 32 и 7 дополнительных проверок native Ollama boundary, JSON Schema, уникальных tool IDs, отказа при ошибке/OOM и обрезанном ответе.
